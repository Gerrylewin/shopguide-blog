Look. Merchants do not want another tool.

They want the ones they already pay for to show up when a shopper is deciding.

That is the complaint on r/shopify and r/shopifyDev. Too many apps. Apps that do not talk. Loyalty programs nobody notices. Reviews that live under the fold. Email capture that dies when the popup closes.

ShopGuide's answer is small. Put the agent on the page. Read the live catalog. Let the partners you already run attach to that same conversation.

## The feature: partners in the on-page conversation

ShopGuide is a theme block. You drop the ShopGuide Chat section in the theme editor. It sits on the page. It opens with context about what the shopper is looking at. It does not wait in a bubble.

During the chat the agent reads the Shopify Catalog API. Stock, variants, price, metafields. That is the base.

Then the partners you connect can ride the same turn.

The public list is on the [integrations page](https://blog.yourshopguide.com/integrations). Rivyo, Judge.me, Klaviyo, Smile.io, Alia, Slack. Each card leads with what the pairing does for the merchant. The how-to lives behind "Learn more."

You do not replace those apps. You give them a mouth inside the conversation that is already happening.

## What each partner actually does for the merchant

Keep the ones you run. Leave the rest alone.

**Judge.me and Rivyo.**
A shopper asks if the moisturizer works for sensitive skin. The agent can pull a matching review and photo proof instead of inventing confidence. You paste a public API token. No token, no review text. Social proof stays in the flow instead of a separate tab.

**Klaviyo.**
The conversation does not die when the visitor leaves. Newsletter capture on the storefront. Profile tags from what they asked. Named events the docs list: ShopGuide Chat Engaged, ShopGuide Order Attributed, ShopGuide NPS Submitted. Klaviyo still owns the flows. ShopGuide hands it the moment.

**Smile.io.**
Points balance, VIP tier, what Gold actually gets them. A shopper can ask "how many points do I have?" and get a number. You generate an API token in Smile.io and paste it. No token, the agent cannot see the balance. Loyalty becomes part of the path to checkout instead of a program nobody notices.

**Alia.**
Openings and picks that match the incentive you already decided to show that visitor. Alia stays the personalization engine. ShopGuide reads the context so the first line is not generic.

**Slack.**
Stuck thread, high cart, "I want a human." Slack gets the alert with customer, cart, and a transcript link. Your team does not reply inside Slack. Resolution stays in Shopify or the ShopGuide admin so the history lives in one place.

That is the list that exists today. Not a roadmap.

## How ShopGuide itself is wired into Shopify

Three places. That is the product.

**1. Theme block.**
One storefront surface. Launch messages, visibility, and styling live in the app admin. Partners are not copied onto the page as extra scripts.

**2. Shopify Admin.**
The dashboard sits in the Shopify admin sidebar. Home, Analytics, Path Explorer, Chats, Integrations, Settings. Numbers live next to the rest of the store. No second login.

**3. Catalog API at talk time.**
Live reads during the conversation. Partner context attaches to that same turn. The shopper does not open a new tab.

Open **ShopGuide → Settings → Integrations**. ShopGuide checks the published theme for app embeds it recognizes. Those apps land at the top under "Looks like you use these," with an **On your store** badge. Detection does not invent credentials. It stops you from hunting logos for tools you already installed. You still paste the key or token for the ones that need it.

## Honest limits

Say this before you flip any switches.

ShopGuide does not replace Klaviyo, Judge.me, Rivyo, Smile.io, Alia, or Slack. Keep the apps that already work.

Detection is a heuristic. It only sees app embeds on the published theme. An app installed but not on the theme will not badge itself. Connect it by hand.

Dirty product data still produces thin answers. The Catalog API keeps stock honest. It does not write your descriptions.

Slack is one-way. Klaviyo, Smile.io, and the review apps need a key or token. A partial stack still works. You do not need every logo.

That is the deal. Native wiring. Partner context when it exists. Not a new operating system.

## Frequently Asked Questions

**What are Shopify integration partners in ShopGuide?**
The apps ShopGuide can read from or write to during a guided session: Klaviyo, Judge.me, Rivyo, Smile.io, Alia, and Slack, plus the native Catalog API. The public list lives on the [integrations page](https://blog.yourshopguide.com/integrations).

**How is ShopGuide integrated into Shopify?**
Three places. A theme block on the storefront. A native app in the Shopify admin for analytics and settings. Direct reads from the Shopify Catalog API during chat. Partner apps attach to that same conversation.

**Do I have to replace my current apps?**
No. Keep the apps that already work. ShopGuide reads them. It does not ask you to rip Klaviyo or Judge.me out.

**Will this add more scripts and slow the storefront?**
ShopGuide is one theme block. Partners are not copied onto the page as extra pixels. The agent reads those systems during the conversation.

**How do I turn a partner on?**
Open ShopGuide → Settings → Integrations. Detection badges what it finds. Klaviyo, Smile.io, Judge.me, and Rivyo still need an API key or token pasted on their card. Slack needs an incoming webhook URL. Alia is on by default.

**What if I only use some of the partners?**
Use the ones you run. A partial stack still works. You do not need every logo on the page.

**Does Slack let my team reply inside Slack?**
No. Slack gets an alert with customer, cart, and a transcript link. Resolution stays in Shopify or the ShopGuide admin so the history lives in one place.
